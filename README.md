# Apple 门店取货监控 · 抢购助手

盯住 Apple Store 的**门市取货（In-Store Pickup）**库存：有货立刻通知你，并且能直接打开购物袋、
把结账流程自动填到「检查订单」页，你只需核对后点「立即下单」。

仓库包含两个可以独立使用、也能联动工作的部分：

| 模块 | 是什么 | 版本 | 运行环境 |
|---|---|---|---|
| **[`Monitior/`](Monitior/README.md)** | 库存监控程序。轮询 Apple 接口，有货发邮件 / 手机推送，并可唤起下单浏览器 | `2.9.0` | Node.js ≥ 18.17 |
| **[`apple-checkout-helper/`](apple-checkout-helper/README.md)** | Chrome 扩展。在结账页一键填完取货信息、发票、支付方式 | `1.10.0` | Chrome（MV3，手动加载） |

> 两个模块互不依赖：只想要库存提醒，装 `Monitior/` 就够了；只想结账时少点几下，装扩展就够了。
> 两个都装，才有下面这条「有货 → 自动结账」的链路。

---

## 联动流程

```
监控发现有货（首次，不含「仍有货」重复提醒）
  → 登记一次性交接令牌（15 分钟有效，只能领一次）
  → 用专用下单 Chrome 打开购物袋
     https://www.apple.com.cn/shop/bag#af-handoff=<令牌>@<设置界面端口>
  → 扩展向 http://127.0.0.1:<端口>/api/handoff/claim 领取「机型 + 有货门店」
  → 扩展：点「结账」→ 选有货门店（按优先门店排序，不可取货就换下一家）
         → 填取货人信息 → 发票 → 支付方式
  → 停在检查订单页，由你核对后点「立即下单」
```

设计上刻意留了几道刹车：

- **默认停在检查订单页**，不会替你下单。要自动点「立即下单」需在扩展设置里显式勾选，勾选时会二次确认
- 交接令牌只在 `127.0.0.1` 上可领，领过或过期即作废
- 短信验证码**永不自动填**，检测到就停下来提示你
- 同一页面连续 3 次无进展、或点按钮 3 秒无反应，自动停手，避免重复提交

## 快速开始

### 一、库存监控（Windows）

1. 装 **Node.js LTS**：<https://nodejs.org>（一路「下一步」，装完建议注销重登一次）
2. 双击 `Monitior/一键部署.bat`
3. 首次会弹配置向导，填 3 项：**收件邮箱**、**发件邮箱**、**QQ 邮箱 16 位 SMTP 授权码**
   （授权码在 QQ 邮箱「设置 → 账号 → IMAP/SMTP 服务」里开启后获取，**不是 QQ 登录密码**）
4. 看到「部署完成」即可，程序从此后台静默运行

> 想要**真正的开机自启**（不登录也跑）：右键 `一键部署.bat` →「以管理员身份运行」。

装好后双击 `打开设置界面.bat`，浏览器打开 <http://127.0.0.1:8787> 选择门店和机型。
界面只监听回环地址，外部网络访问不到。改完点「保存并生效」立即生效，不用重启。

macOS / Linux 用 `npm install && npm start`，systemd 与 launchd 配置在 `Monitior/scripts/` 下。

### 二、结账扩展（Chrome）

1. 打开 `chrome://extensions/`，右上角开启**开发者模式**
2. 点「加载已解压的扩展程序」，选择 `apple-checkout-helper/` 文件夹
3. 首次安装会自动弹出配置页，把姓名、手机号、邮箱、取货门店等信息填一遍（边填边自动保存）

结账页右下角会出现悬浮按钮，点一下即自动填写；也可以按 <kbd>Alt</kbd>+<kbd>Q</kbd>。

> Chrome 137 起不支持命令行加载扩展，必须走上面的手动步骤。
> 也可以直接下载 [Releases](releases) 里的 `apple-checkout-helper-v1.10.0.zip` 解压后加载。

## 功能要点

**监控（`Monitior/`）**

- 默认**深圳专属模式**：只查深圳 3 家门店（益田假日广场 / 万象城 / 前海壹方城），大陆其他城市与港澳一个请求都不发
- 深圳通道常规 **5 秒**、放货时段 **3 秒**轮询
- 机型 → 容量 → 颜色**三级下拉**自选，覆盖 iPhone 全品类共 73 种配置组合；也可手输料号加目录外机型
- 接口抽风时**不会误报「无货」**：哨兵校验 + 会话预热 + 「库存未知」态
- 只在状态变化时通知，不刷屏；邮件走 QQ SMTP，可选 Bark 手机推送（重要警告可穿透静音）
- 崩溃自动重启、开机自启、后台无窗口
- 通知先落盘再发送，SMTP 接受后才确认成功，重启后仍保留待发事件

**扩展（`apple-checkout-helper/`）**

- 识别页面类型（选日期 / 填取货人 / 发票 / 支付方式 / 检查订单）逐步推进
- 门店按「精确名 → 关键词 → 第一个可取货」匹配，取不到就换下一家
- 支付方式可选「我自己点」或自动，默认前者
- 数据只存在 `chrome.storage.local`，**不上传**；唯一的外部连接是本机 `127.0.0.1` 的监控程序
- 支持导出 / 导入配置，换电脑不用重填

## 配置与隐私

- **本仓库不含任何个人配置**：邮箱、SMTP 授权码、Bark key、姓名、手机号、身份证、收货地址、Apple 登录 cookie 一律不入库
- 你的真实配置只落在本地：`Monitior/.env`（邮箱凭据）、`Monitior/config.json`（门店与机型）、
  `Monitior/browser-profile/`（专用下单浏览器的 Chrome 配置，含登录 cookie）、扩展的 `chrome.storage.local`
- 上述文件与 `state.json`、`monitor.log`、`data/`、`node_modules/`、`*.zip` 均已在 `.gitignore` 中排除
- 迁移电脑时**只带源码和 `catalog-cache.json`**，`.env` 由邮箱向导重新生成

## 已知限制

- 扩展只在 `apple.com.cn` / `apple.com` 生效
- 页面类型靠文案判断，Apple 大改文案时会显示「未识别页面」，需要在扩展里「记录本页字段」后补规则
- 同一时间**只跑一个监控实例**，多开会重复通知（各自状态文件不同步）
- 通知是「至少一次」投递：SMTP 部分拒收或发送后写盘失败，可能出现重复邮件
