# Apple Store 全中国 · 门市取货监控

监控 **中国大陆 + 香港** Apple Store 的**门市取货（In-Store Pickup）**库存，有货时发邮件通知你。

**城市、门店、机型、容量、颜色全部在网页界面里用下拉框自己选**，不是写死在代码里。

- 🖱️ **Windows 一键部署**：双击 `一键部署.bat`，第一次问你一次邮箱信息，之后全自动
- 🎛️ **本地设置界面**：双击 `打开设置界面.bat`，**先选城市 → 再选门店**，机型用三级下拉
- 🇨🇳 **全中国覆盖**：27 个城市、57 家 Apple Store（大陆 25 城 49 家 + 香港 6 家 + 澳门 2 家）
- 📱 **iPhone 全品类**：Duo / 18 Pro Max / 18 Pro / Air / 17 / 17e / 16，共 73 种配置组合
- 🫥 **后台静默运行**：没有黑窗口弹出来，不打扰你正常用电脑
- 📧 用你的 **QQ 邮箱**发信，通知送到你的 **Outlook 邮箱**
- 🔁 崩溃自动重启、开机（或登录）自动启动
- 🧠 接口抽风时**不会误报「无货」**（内置哨兵校验 + 会话预热）
- 🔕 只在状态变化时发邮件，不刷屏

## 一、一键部署（Windows）

1. 把整个文件夹解压到任意位置
2. 安装 **Node.js LTS**：<https://nodejs.org> → 下载 → 一路「下一步」
   （已装过就跳过；装完最好注销重登一次）
3. **双击 `一键部署.bat`**
4. 第一次会弹出配置向导，按提示输入 3 项：
   - **收件邮箱** → 你的 Outlook 邮箱（有货通知发到这里）
   - **发件邮箱** → 你的 QQ 邮箱
   - **授权码** → QQ 邮箱的 16 位 SMTP 授权码（见下方获取方法）
5. 看到「部署完成」就成了。程序从此在后台静默运行。

> 想要**真正的开机自启**（不用登录就运行）：右键 `一键部署.bat` →「以管理员身份运行」。
> 不这么做也能用，只是要等你登录后才开始监控。

### 怎么拿 QQ 邮箱的授权码

1. 电脑浏览器登录 <https://mail.qq.com>
2. 左上角 **设置 → 账号**
3. 往下找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」**
4. 把 **「IMAP/SMTP 服务」** 打开（要发一条短信验证）
5. 验证后弹出一串 **16 位授权码**，复制它 —— 这就是要填的授权码

> ⚠️ 授权码 ≠ QQ 登录密码。

## 二、设置界面（选择监控什么）

双击 **`打开设置界面.bat`**，浏览器会打开 <http://127.0.0.1:8787>。

界面只监听本机回环地址（`127.0.0.1`），**外部网络访问不到**。

| 区块 | 能做什么 |
|---|---|
| **1. 优先取货门店** | **先选城市，再选门店**（级联下拉）。这家一有货就发「急」邮件 |
| **2. 同时监控的门店** | 再选几家当「备选」，它们有货时发「备选」邮件。可跨城市、可跨地区 |
| **3. 监控机型** | **机型 → 容量 → 颜色** 三级下拉，选好点「添加」。也可一键添加整个容量的所有颜色 |
| **4. 已选监控目标** | 列出实际会盯的机型（含大陆/香港两地的料号），可单个移除 |
| **5. 监控行为** | 轮询间隔、是否只关注优先门店、持续有货重复提醒间隔、库存消失是否通知 |
| **6. 通知邮箱** | 只读展示当前收发件邮箱，可一键发送测试邮件 |
| **运行状态** | 每个机型最近一次检查结果、优先门店是否命中、附近还有哪些门店有货 |
| **运行日志** | 最近 120 行，每 20 秒自动刷新 |

点 **「保存并生效」** 后**立即生效，不用重启程序**（内部会自动重建 Apple 会话）。

**「↻ 刷新机型目录」** 会重新从 Apple 官网抓取机型/容量/颜色/价格（约 3 秒）——
Apple 上新品或调价后点一下即可。也可以手动输入料号（如 `MJXU4ZA/A`）添加目录外的机型。

#### 为什么澳门查不了

Apple 澳门**只有零售店，没有网上商店**：`https://www.apple.com/mo/` 只有门店信息页，
`/mo/shop/...` 一律返回 403「Page Not Found」。没有网上商店就没有在线库存接口，
所以程序**查不到**澳门的取货库存。

界面上澳门的两家门店仍然会列出来（能看地址电话），但选了会给出明确提示，
也不会被设为监控目标 —— 而不是让你选完以后以为它在监控、其实一直查不到。

## 七、配置文件

分两个文件，各管一摊：

### `config.json` —— 界面可改（门店 / 机型 / 行为）

由设置界面自动生成和写入，也可以手工编辑（程序每隔一轮检测变化并热加载）。

```json
{
  "version": 2,
  "priorityStore": "R499",
  "watchStores": ["R499", "R401", "R484"],
  "priorityOnly": false,
  "soldOutNotify": true,
  "repeatAlertMinutes": 15,
  "pollIntervalSeconds": 60,
  "uiPort": 8787,
  "targets": [
    {
      "key": "iPhone 18 Pro Max|512GB|Silver",
      "name": "iPhone 18 Pro Max 512GB 银色",
      "parts": { "CN": "MJYC4CH/A", "HK": "MJXU4ZA/A" },
      "buyUrls": { "CN": "https://...", "HK": "https://..." }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `priorityStore` | 优先门店编号，如 `R499`（广东道）、`R401`（上海环贸 iapm） |
| `watchStores` | 要监控的门店编号数组，自动包含 `priorityStore`；澳门门店会被拒绝 |
| `priorityOnly` | `true` = 只有优先门店有货才通知 |
| `repeatAlertMinutes` | 持续有货时每隔几分钟再提醒；`0` = 只提醒一次 |
| `pollIntervalSeconds` | 轮询间隔，最小 30 秒 |
| `uiPort` | 设置界面端口，默认 8787 |
| `targets` | 监控目标：`key` 是「机型\|容量\|颜色」，`parts` 是两地料号 |

> **旧版配置会自动升级**：以前 `config.json` 里的 `cantonOnly` 会变成 `priorityOnly`，
> 只有单个 `partNumber` 的目标会按料号后缀自动推断地区（`CH`→大陆，`ZA`/`ZP`→香港），
> 下次在界面里保存时再补全成两地料号。不需要手动改。

### `.env` —— 邮箱凭据（界面不碰，更安全）

由邮箱配置向导生成。想换服务商时改这几项：

| 服务商 | SMTP_HOST | PORT | SECURE |
|---|---|---|---|
| QQ | `smtp.qq.com` | 465 | true |
| 163 | `smtp.163.com` | 465 | true |
| Gmail | `smtp.gmail.com` | 465 | true（应用专用密码） |
| Outlook | `smtp-mail.outlook.com` | 587 | **false** |

> 多收件人：`MAIL_TO` 用英文逗号分隔。

## 九、常见问题

**Q：双击 `一键部署.bat` 提示没有 Node.js？**
A：先装 Node.js LTS（<https://nodejs.org>），装完**注销重登**或重开命令窗口，再双击。

**Q：配置向导报「SMTP 登录失败」？**
A：99% 是授权码填错。必须填 QQ 邮箱的 **16 位授权码**（不是登录密码），
且要先在 QQ 邮箱里**开启 IMAP/SMTP 服务**。

**Q：测试邮件发了，Outlook 收件箱没有？**
A：先翻 **垃圾邮件箱**，把发件人（你的 QQ 邮箱）加白名单。QQ 发 Outlook 进垃圾箱很常见。

**Q：设置界面打不开？**
A：双击 `打开设置界面.bat` 会自动启动服务再开浏览器（首次可能要等几秒装依赖）。
浏览器没反应就手动访问 <http://127.0.0.1:8787>。
如果程序正在后台监控，界面本来就是开着的，这个脚本只会帮你打开浏览器。

**Q：改完设置要不要重启程序？**
A：不用。点「保存并生效」后端会立刻按新配置跑（内部重建 Apple 会话、重新定位）。

**Q：澳门为什么选不了 / 选了没反应？**
A：Apple 澳门没有网上商店，官方不提供在线库存，程序查不到。
界面上会显示「Apple 澳门没有网上商店，无法查询门店取货库存」并禁用选择。

**Q：我选了上海的门店，为什么邮件里会出现苏州、无锡的门店？**
A：这是 Apple 接口的特性，不是 bug。大陆的库存接口是**按定位返回"附近"有货门店**，
定位上海时会把苏州、无锡、杭州、宁波的门店一起返回来。
程序只会把**你勾选了监控的门店**算进结果，其余的在界面里作为
「附近另有 N 家未监控门店有货」提示你 —— 相当于免费送了你一份周边库存情报。

**Q：界面里的机型目录是实时的吗？**
A：`catalog-cache.json` 里预置了一份抓好的目录，所以首次打开就能直接选。
点「刷新机型目录」会从 Apple 官网重新抓取（约 3 秒）。

**Q：怎么确认它真的在后台跑？**
A：双击 `查看日志.bat`，正常每隔 60 秒会有一行 `#N 检查完成`。

**Q：日志里出现 `[校验:大陆] 第 N 次：哨兵无数据…`？**
A：这是**正常的自愈机制**。Apple 的接口在会话刚建立、或刚换过定位时经常返回空数据，
程序会自动预热重试，只有拿到可信数据才算一轮有效检查。
所以你**不会**因为接口抽风而收到错误的「无货」结论。

**Q：会不会被 Apple 封 IP？**
A：默认 60 秒一次，每次轮询带 0–5 秒随机抖动；会话在多次轮询间复用。
这个频率非常保守。不建议把间隔调到 30 以下。

**Q：会不会误报「有货」？**
A：不会。判定依据是 Apple 返回的 `eligibleStores` 是否包含你选的门店编号。
而且每轮都带一个「哨兵料号」（长期有货的 iPad 配件）做健康检查：
哨兵没数据 → 判定本轮不可信 → 重试，绝不把接口故障当成库存结论。
大陆和香港各有自己的哨兵料号。

**Q：程序会打扰我正常用电脑吗？**
A：不会。后台通过隐藏窗口的启动器运行（`wscript` + VBS），
任务管理器里能看到 `node.exe`，但**不会弹出任何窗口、不抢焦点、不弹通知**。
设置界面是你主动开浏览器才出现的，不占桌面。

**Q：电脑睡眠/关机还监控吗？**
A：睡眠会暂停。笔记本建议设成「接通电源时不睡眠」；
或部署到常开的机器 / 树莓派 / 云服务器（用 Docker 最省事）。

## 十、工作原理（技术备注）

### 接口协议（2026-09 实测）

Apple 的门市取货数据在同一套接口下，**大陆和香港都能用**，但有两处关键差异：

1. **老接口 `/shop/fulfillment-messages` —— 已下线，全局返回 404。**
   网上多数现成的 Apple 抢购监控脚本用的都是它，现在都已经跑不通。

2. **现行接口 `/shop/sba/availability-message`** —— 三个坑：

   - **必须先建立 SBA 会话**：先 GET 商品页拿到 `fnode` 令牌，再调
     `/shop/sba/d/init?fnode=...`。不建会话的话，接口只返回送货信息，
     `partAvailableStoresCount` **恒为 0** —— 这是**假无货**，
     HTTP 200、JSON 结构完整，非常有迷惑性。

   - **会话刚建立后的第一次查询偶发返回空数据**，所以程序做了
     「预热 + 哨兵校验 + 重试」。

   - **🇨🇳 大陆必须先提交定位，否则永远返回 0 家店**（同样是假无货）：
     ```
     GET /shop/address/location/update?state=省&city=市&district=区
     ```
     其中 **`district`（区）是必填** —— 缺了它接口一样返回 0，
     这点没有任何文档说明，是踩出来的。
     提交定位后，`eligibleStores` 返回的是**定位点附近有货的门店**，
     会跨市（定位上海能拿到苏州/无锡/杭州的门店），
     所以用户勾选的每个城市都要单独提交一次定位。

拿到数据后，`eligibleStores` 字段就是「哪些门店有货」的门店编号列表。

### 门店与定位数据

- **门店目录**：抓自 `apple.com.cn/retail/storelist/` 页面里内嵌的
  `__NEXT_DATA__` JSON（含门店编号、名称、地址、电话、省市）。
  生成结果固化在 `src/stores.js`，离线可用。
- **行政区**：大陆的定位需要「区」，取自 Apple 自己的
  `/shop/address/locality-lookup` 接口，并且**优先采用门店地址里真实出现的那个区**
  （直接取第一项常常会拿到"长沙县""登封市"之类的郊县，把定位带偏）。

### 机型目录与直达链接

机型目录来自 Apple 各购买页内嵌的 products JSON（含料号/容量/颜色/价格）。
两地页面结构一致，但**导购链接的 slug 规则完全不同**：

- **大陆**：slug 就是**料号的小写形式** ——
  `/shop/buy-iphone/iphone-18-pro/mjyc4ch/a` ✅ 精确到具体颜色
- **香港**：slug 是中文描述 ——
  `/shop/buy-iphone/iphone-18-pro/6.9-吋顯示器-512gb-銀色`

香港这种要靠颜色名翻译反推，所以程序**用页面上真实存在的 slug 集合做校验**：
推不出来就退回机型主页，绝不给出一个 404 的链接。（实测 73×2 = 146 条链接全部精确命中）

> 顺带一个坑：Apple 的商品名里混了普通空格和 `U+00A0` 不换行空格，
> 大陆页用前者、香港页用后者，**同一页里甚至两种都有**。
> 不统一就会把同一款机型拆成两条记录，界面上出现两个"iPhone Duo"。

> Apple 随时可能再改接口。若某天 `--once` 持续报错，多半是又变了；
> 看 `node src/index.js --once` 的具体错误，再对照 `src/apple.js` 顶部注释调整。

## 十二、迁移到另一台电脑

本项目**不含任何硬编码路径**，整个文件夹拷过去、双击 `一键部署.bat` 即可
（已实测：干净环境从零部署 → 装依赖 → 邮箱向导 → 后台任务，全程通过）。

**要带**：全部源码与本目录下的文件，**包括 `catalog-cache.json`**
（里面是预置好的机型目录，带上它新机器首次打开界面就能直接选机型，不用等抓取）

**不用带**（新机器会自动生成）：
`node_modules/`、`.env`（邮箱向导会重新问）、`config.json`（用默认值，进界面重选）、
`monitor.log`、`state.json`、`data/`

> ⚠️ **同一时间只跑一个实例**。多开会导致重复邮件（各自的状态文件不同步）。
> 迁移时记得先在旧机器上双击 `卸载监控.bat`。

**走代理才能上网的环境**：

```bash
# Windows PowerShell
$env:HTTPS_PROXY='http://127.0.0.1:7890'; node src/index.js --once
# Linux / macOS
export HTTPS_PROXY=http://127.0.0.1:7890; node src/index.js --once
```
