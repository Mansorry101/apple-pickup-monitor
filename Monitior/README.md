# Apple Store 门市取货监控

当前配置为监控 **深圳 3 家 Apple Store** 的门市取货（In-Store Pickup）库存，有货时发邮件及手机通知你。

**机型、容量、颜色全部在网页界面里用下拉框自己选**，不是写死在代码里。

- 🖱️ **Windows 一键部署**：双击 `一键部署.bat`，第一次问你一次邮箱信息，之后全自动
- 🎛️ **本地设置界面**：双击 `打开设置界面.bat`，机型用**三级下拉**；门店锁定深圳 3 家
- 📱 **iPhone 全品类**：Duo / 18 Pro Max / 18 Pro / Air / 17 / 17e / 16，共 73 种配置组合
- 🫥 **后台静默运行**：没有黑窗口弹出来，不打扰你正常用电脑
- 🔁 崩溃自动重启、开机（或登录）自动启动
- 🧠 接口抽风时**不会误报「无货」**（内置哨兵校验 + 会话预热）
- 🔕 只在状态变化时发邮件，不刷屏
- 🛒 **有货自动下单**：发现有货立刻用**专用的下单 Chrome** 打开购物袋，交给「Apple 结账速填」扩展（1.10.0+）结账、填取货信息，停在检查订单页（见下文「有货自动下单」）

- 想恢复以前「大陆多城市 + 香港」的监控范围：把 `config.json` 里的
- `"shenzhenOnly"` 改成 `false`，重启程序即可（设置界面会重新出现城市 / 门店选择）。

## 有货自动下单（联动「Apple 结账速填」扩展）

监控发现有货后，不只是发邮件，还会直接打开浏览器把下单交给扩展。**要买的机型请提前加进购物袋**，程序只打开购物袋，不替你加购：

```
监控发现有货（首次，不含「仍有货」提醒）
  → 登记一次性交接令牌（15 分钟有效，只能领一次）
  → 用专用下单 Chrome（browser-profile/）打开购物袋：https://www.apple.com.cn/shop/bag#af-handoff=<令牌>@<设置界面端口>
  → 扩展向 http://127.0.0.1:<端口>/api/handoff/claim 领取机型和有货门店
  → 扩展：点「结账」（购物袋是空的或超过限购就停下等你）
         → 选有货门店（按优先门店排序，第一家不可取货就换下一家）→ 取货人信息 → 发票 → 支付方式
  → 停在检查订单页，你核对后点「立即下单」
```

**专用下单浏览器**

下单用的是一个独立的 Chrome 配置，数据放在程序目录的 `browser-profile/` 里（Chrome 的 `--user-data-dir`）。它和你日常用的 Chrome 完全分开：

- 不带日常 Chrome 里的旧 cookie。日常 Chrome 登录不上 Apple、无痕却能登录时，多半就是旧 cookie 的问题，用它就能绕开
- 和无痕不一样，**登录状态和购物袋会一直保存**，所以提前登录、提前加购都有效
- 扩展要在这个配置里**单独装一次**（日常 Chrome 里装的扩展它看不到）
- `browser-profile/` 里有 Apple 的登录 cookie，别发给别人；删掉它就等于退出登录、清空这个浏览器

**准备工作（一次性）**

1. 双击 **`打开下单浏览器.bat`**（或设置界面 →「有货自动下单」→「打开下单浏览器」），会弹出一个新的 Chrome 窗口，打开 Apple 购物袋
2. 在这个窗口里：
   - **登录 Apple 账户**（结账要登录；登录墙扩展不会代填，没登录时它会停在登录页等你）
   - 把要买的机型**加进购物袋**
   - 打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选 `apple-checkout-helper`（**1.10.0 或更高**），在扩展设置页填好取货人、手机号、身份证后四位等
3. 弄好后这个窗口可以关掉，也可以一直开着。有货时监控会自动打开它；它开着的话，就在里面新开一个标签页
4. 监控程序要带设置界面运行（默认就是；不要加 `--no-ui`），扩展靠它领取交接信息
5. 打开设置界面 →「有货自动下单」→ 点 **测试联动**：会打开购物袋，扩展面板显示「已接手（测试）」、设置界面显示「已接手」就说明通了。测试**不会**点结账

**设置项**（设置界面里都能改）

| 项 | 默认 | 说明 |
|---|---|---|
| `autoCheckout` | `true` | 有货时自动打开浏览器交接；关掉就只发通知 |
| `checkoutBrowser` | `chrome` | `chrome` / `edge` / 浏览器 exe 完整路径 |
| `checkoutProfile` | `true` | 用专用下单配置（`browser-profile/`）；关掉就用日常浏览器，那它必须装了扩展并已登录 |
| `checkoutCooldownMinutes` | `10` | 交接一次后，这段时间内不再重复弹浏览器 |

**边界**

- 只交接**大陆**机型（扩展只支持 apple.com.cn 结账）；一次只交接一个机型：优先门店有货的优先，其次按机型列表顺序
- 默认停在检查订单页，不会替你点「立即下单」；扩展设置里打开了「自动点立即下单」才会点
- 电脑要处于**已登录桌面**的状态：开机后还没登录 Windows 时，浏览器窗口打不开
- 交接令牌只在本机 127.0.0.1 上领取，只接受扩展来源的请求，领过或过期就作废

## 深圳专属模式做了什么

这一版把监控范围硬锁在深圳，不是靠「你只选深圳门店」这种约定：

| 位置 | 行为 |
|---|---|
| `src/settings.js` | `shenzhenOnly: true` 时，`priorityStore` 只能是深圳门店，`watchStores` 恒为深圳 3 家；`szIntervalSeconds` 直接取 `hkIntervalSeconds`，`rushSzIntervalSeconds` 取 `rushHkIntervalSeconds` |
| `src/scheduler.js` | `selectLanes({ szOnly: true })` 只返回深圳一条通道 —— 大陆整轮、香港整轮、优先通道都不派发 |
| `src/index.js` | 没有可跑通道时**不会退回大陆整轮**，而是明确报错空转，避免绕过屏蔽 |
| `src/webui-page.js` | 城市下拉只剩「深圳」，3 家门店固定不可增删，大陆 / 香港 / 优先的间隔输入框置灰 |

查询节奏（默认）：

| 通道 | 常规 | 放货时段 |
|---|---|---|
| 深圳（唯一通道，3 家门店） | **5 秒** | **3 秒** |
| 大陆全部门店| 不运行 | 不运行 |
| 香港全部门店| 不运行 | 不运行 |
| 优先门店 + 优先机型 | 不运行 | 不运行 |

## 故障时的行为

- 切换优先门店会替换旧的主门店，不会自动把旧门店留作备选；如需两地同时监控，请通过“添加门店”明确添加。修改选择后隐藏旧结果，点击“立即检查一次”会先保存选择。
- 端口已被旧实例占用时，新进程会退出并提示关闭旧实例，避免新旧监控同时运行、浏览器仍连接旧界面。界面顶部会显示当前版本 `2.3.0`。
- 机型版本跟随监控门店：只选大陆门店只查大陆料号，只选香港门店只查香港料号；两地都选时分别查询当地版本。机型列表只显示所选地区的料号和价格，结果与邮件按地区对应门店和购买链接。缺少当地料号时不会用另一地区版本替代。
- 大陆、香港独立查询；成功地区先更新库存并触发通知，不等待其他地区重试完成。
- 每批请求校验哨兵、目标料号和库存字段。数据缺失或查询失败显示“库存未知”，不会据此发送售罄通知。
- 通知先写入待发送状态，SMTP 接受后才确认成功。发送失败时，后续检查确认库存状态仍然适用才重试；重启后仍保留待发送事件。
- 不同类别邮件独立发送，一封失败不会阻断其他通知。库存变化后取消过期的待发送事件。
- 这是至少一次发送：SMTP 部分拒收，或发送成功后程序退出、写盘失败，可能导致部分收件人收到重复通知。
- `--dry-run` 不修改正式状态文件。手动检查与自动轮询排队，避免会话定位互相干扰。
- 界面顶部状态栏会反映邮箱连通性：SMTP 登录失败时变红并写明原因。此时库存查询照常运行，但通知发不出去，请及时处理。

离线回归测试：`npm test`，包括发信失败、重启重试、地区失败隔离和异常响应；不发送真实邮件。

## 一、一键部署（Windows）

1. 把整个文件夹解压到任意位置
2. 安装 **Node.js LTS**：<https://nodejs.org> → 下载 → 一路「下一步」
   （已装过就跳过；装完最好注销重登一次）
3. **双击 `一键部署.bat`**
4. 第一次会弹出配置向导，按提示输入 3 项：
   - **收件邮箱** → 你的收件邮箱（有货通知发到这里）
   - **发件邮箱** → 你的QQ邮箱
   - **授权码** → QQ 邮箱的 16 位 SMTP 授权码（见下方获取方法）
5. 看到「部署完成」就成了。程序从此在后台静默运行。

> 想要**真正的开机自启**（不用登录就运行）：右键 `一键部署.bat` →「以管理员身份运行」。
> 不这么做也能用，只是要等你登录后才开始监控。

### 怎么拿 QQ 邮箱的授权码

1. 电脑浏览器登录 <https://mail.qq.com>
2. 左上角 **设置 → 账号**
3. 往下找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」**
4. 把 **「IMAP/SMTP 服务」** 打开（要发一条短信验证）
5. 验证后弹出一串 **16 位授权码**，复制它 —— 这就是要填的授权码

> ⚠️ 授权码 ≠ QQ 登录密码。

## 二、设置界面（选择监控什么）

双击 **`打开设置界面.bat`**，浏览器会打开 <http://127.0.0.1:8787>。

界面只监听本机回环地址（`127.0.0.1`），**外部网络访问不到**。

| 区块 | 能做什么 |
|---|---|
| **1. 优先取货门店** | 城市固定「深圳」，3 家门店可选（级联下拉）。这家一有货就发「急」邮件 |
| **2. 同时监控的门店** | 深圳 3 家固定全部监控（不可增删），其余门店有货时发「备选」邮件 |
| **3. 监控机型** | **机型 → 容量 → 颜色** 三级下拉，选好点「添加」。也可一键添加整个容量的所有颜色 |
| **4. 已选监控目标** | 列出实际会盯的机型（仅显示已选门店地区的料号），可单个移除 |
| **5. 监控行为** | **深圳通道间隔**（与香港同速）、是否只关注优先门店、持续有货重复提醒间隔、库存消失是否通知；大陆 / 香港 / 优先的输入框已置灰 |
| **6. 通知邮箱** | 只读展示当前收发件邮箱，可一键发送测试邮件 |
| **运行状态** | 每个机型最近一次检查结果、优先门店是否命中、附近还有哪些门店有货 |
| **运行日志** | 最近 120 行，每 20 秒自动刷新 |

点 **「保存并生效」** 后**立即生效，不用重启程序**（内部会自动重建 Apple 会话）。

**「↻ 刷新机型目录」** 会重新从 Apple 官网抓取机型/容量/颜色/价格（约 3 秒）——
Apple 上新品或调价后点一下即可。也可以手动输入料号（如 `MJXU4ZA/A`）添加目录外的机型。

#### 为什么澳门查不了

Apple 澳门**只有零售店，没有网上商店**：`https://www.apple.com/mo/` 只有门店信息页，
`/mo/shop/...` 一律返回 403「Page Not Found」。没有网上商店就没有在线库存接口，
所以程序**查不到**澳门的取货库存。

界面上澳门的两家门店仍然会列出来（能看地址电话），但选了会给出明确提示，
也不会被设为监控目标 —— 而不是让你选完以后以为它在监控、其实一直查不到。

> 机型目录是**实时从 Apple 官网抓的**，不是硬编码。Apple 上新品或调价后，
> 点界面上的「↻ 刷新机型目录」即可。

> 💡 **同一款机型在大陆和香港的料号不一样**（大陆 `CH/A`、香港 `ZA/A`）。
> 你只需要选一次机型加颜色，
> 程序按已选门店的地区匹配当地料号；同时选择两地门店时，分别查询大陆与香港版本。


| | 香港 | 深圳通道 | 大陆整轮 |
|---|---|---|---|
| 需要提交定位 | 否 | **是**（广东省 / 深圳市 / 区） | 是（每个监控城市一次） |
| 一次请求覆盖 | 全港 6 家 | 深圳 3 家 | 所有监控城市 |
| 默认间隔 | 5 秒 | **5 秒** | 60 秒 |
| 放货时段间隔 | 3 秒 | **3 秒** | 15 秒 |
| 会话 / 定位复用 | 是 | 是（跨轮次复用，只在必要时重建） | 是 |

- 深圳通道**只在监控门店里有深圳门店、且它比大陆整轮更短时**才会启用；
  否则深圳门店由大陆整轮覆盖，不会重复请求。
- 它**只确认深圳的门店**：如果同时还监控了北京，深圳通道不会替北京下「无货」结论，
  界面上北京的结果会沿用完整轮次的数据。
- 监控列表里**只有深圳门店**时（默认就是这种情况），优先通道会被自动跳过 ——
  它和深圳通道查的是同一个城市，没必要重复请求；界面上会显示「已被深圳通道覆盖」。
- 深圳 3 家门店的定位行政区是逐店核对过的（前海壹方城 → 宝安区、深圳万象城 → 罗湖区、
  深圳益田假日广场 → 南山区）。**区填错会把定位带偏、漏掉真实有货的门店**，
  所以新增城市时请照门店地址核对 `src/stores.js` 里的 `district`。

```bash
chmod +x deploy.sh && ./deploy.sh
```

## 六、命令行用法

```bash
node src/index.js                 持续监控 + 启动设置界面
node src/index.js --ui-only       只打开设置界面，不监控（纯配置用）
node src/index.js --no-ui         只监控，不启动设置界面
node src/index.js --setup         重新运行邮箱配置向导
node src/index.js --once          只查一次库存，打印结果，不发邮件
node src/index.js --test-email    发一封测试邮件
node src/index.js --simulate      模拟一次真实「有货」告警，验证整条链路
node src/index.js --dry-run       持续监控但只记录、不发邮件
node src/index.js --help          帮助
```

**`--simulate` 是最有用的自检**：它拿一款长期有库存的 iPad 配件冒充你的目标机型，
走完「查到有货 → 判定优先门店 → 渲染中文邮件 → 发信」整个流程，
让你在真正放货之前就确认告警链路是通的。邮件主题带「模拟测试·请忽略」。

开发自测：

```bash
npm test              # 配置校验 + 告警状态机（纯逻辑，不联网）
npm run test:ui       # 无头浏览器真的渲染一遍设置界面，检查下拉框
npm run test:live     # 真实联网：大陆 + 香港的有货识别
npm run build-catalog # 重新抓取机型目录并写入 catalog-cache.json
```

> `test:ui` 需要本机装有 Chrome 或 Edge；没有会自动跳过。
> 它会用 DevTools Protocol 读回每个下拉框的选项数 —— 设置界面的选项是 JS
> 运行时才填的，光看源码或抓 HTML 都发现不了「下拉框是空的」这类问题。

## 七、配置文件

分两个文件，各管一摊：

### `config.json` —— 界面可改（门店 / 机型 / 行为）

由设置界面自动生成和写入，也可以手工编辑（程序每隔一轮检测变化并热加载）。

```json
{
  "version": 2,
  "shenzhenOnly": true,
  "priorityStore": "R484",
  "watchStores": ["R484", "R761", "R793"],
  "priorityOnly": false,
  "soldOutNotify": true,
  "repeatAlertMinutes": 15,
  "pollIntervalSeconds": 60,
  "szIntervalSeconds": 5,
  "uiPort": 8787,
  "targets": [
    {
      "key": "iPhone 18 Pro Max|512GB|Silver",
      "name": "iPhone 18 Pro Max 512GB 银色",
      "parts": { "CN": "MJYC4CH/A", "HK": "MJXU4ZA/A" },
      "buyUrls": { "CN": "https://...", "HK": "https://..." }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `shenzhenOnly` | **默认 `true`**：只查深圳 3 家门店。开启时 `priorityStore` / `watchStores` 被锁在深圳，`szIntervalSeconds` 取 `hkIntervalSeconds`；改成 `false` 恢复多城市 / 跨地区监控 |
| `priorityStore` | 优先门店编号，深圳专属模式下只能是 `R484` / `R761` / `R793` |
| `watchStores` | 深圳专属模式下恒为深圳 3 家（自动补全，不受这里写什么影响）；关闭后自动包含 `priorityStore`，澳门门店会被拒绝 |
| `priorityOnly` | `true` = 只有优先门店有货才通知 |
| `repeatAlertMinutes` | 持续有货时每隔几分钟再提醒；`0` = 只提醒一次 |
| `pollIntervalSeconds` | 两轮开始之间的轮询间隔（大陆），最小 15 秒 |
| `hkIntervalSeconds` | 香港单独的轮询间隔，最小 3 秒、默认 5 秒；香港不用定位、一次请求就出结果，可以查得更勤 |
| `szIntervalSeconds` / `rushSzIntervalSeconds` | **深圳通道**的轮询间隔，最小 3 秒、默认 5 秒（放货时段默认 3 秒）。只查深圳这一个城市（3 家门店），保留大陆必需的省/市/区定位；只在监控门店里有深圳门店、且比大陆整轮更短时启用 |
| `priorityBoost` / `priorityIntervalSeconds` | 优先通道：只查优先门店所在城市的优先机型（`targets[].priority: true`，都不标则全部机型），默认开启、20 秒，最小 5 秒；只有比所在地区整轮更勤时才启用 |
| `rushEnabled` / `rushStart` / `rushEnd` | 放货时段（北京时间，默认 06:00–09:00），时段内改用下面三个高速间隔 |
| `rushPollIntervalSeconds` / `rushHkIntervalSeconds` / `rushPriorityIntervalSeconds` | 放货时段的大陆 / 香港 / 优先通道间隔，默认 15 / 3 / 8 秒，下限同常规 |

被 Apple 限流（HTTP 429 / 503）时，该地区自动暂停 1 分钟，连续限流翻倍，最长 5 分钟，查询成功一次即恢复。
| `uiPort` | 设置界面端口，默认 8787 |
| `targets` | 监控目标：`key` 是「机型\|容量\|颜色」，`parts` 是两地料号 |

> **旧版配置会自动升级**：以前 `config.json` 里的 `cantonOnly` 会变成 `priorityOnly`，
> 只有单个 `partNumber` 的目标会按料号后缀自动推断地区（`CH`→大陆，`ZA`/`ZP`→香港），
> 下次在界面里保存时再补全成两地料号。不需要手动改。

### `.env` —— 邮箱凭据（界面不碰，更安全）

由邮箱配置向导生成。想换服务商时改这几项：

| 服务商 | SMTP_HOST | PORT | SECURE |
|---|---|---|---|
| QQ | `smtp.qq.com` | 465 | true |
| 163 | `smtp.163.com` | 465 | true |
| Gmail | `smtp.gmail.com` | 465 | true（应用专用密码） |
| Outlook | `smtp-mail.outlook.com` | 587 | **false** |

> 多收件人：`MAIL_TO` 用英文逗号分隔。

## 九、常见问题

**Q：双击 `一键部署.bat` 提示没有 Node.js？**
A：先装 Node.js LTS（<https://nodejs.org>），装完**注销重登**或重开命令窗口，再双击。

**Q：配置向导报「SMTP 登录失败」？**
A：99% 是授权码填错。必须填 QQ 邮箱的 **16 位授权码**（不是登录密码），
且要先在 QQ 邮箱里**开启 IMAP/SMTP 服务**。

**Q：测试邮件发了，Outlook 收件箱没有？**
A：先翻 **垃圾邮件箱**，把发件人（你的 QQ 邮箱）加白名单。QQ 发 Outlook 进垃圾箱很常见。

**Q：设置界面打不开？**
A：双击 `打开设置界面.bat` 会自动启动服务再开浏览器（首次可能要等几秒装依赖）。
浏览器没反应就手动访问 <http://127.0.0.1:8787>。
如果程序正在后台监控，界面本来就是开着的，这个脚本只会帮你打开浏览器。

**Q：改完设置要不要重启程序？**
A：不用。点「保存并生效」后端会立刻按新配置跑（内部重建 Apple 会话、重新定位）。

**Q：澳门为什么选不了 / 选了没反应？**
A：Apple 澳门没有网上商店，官方不提供在线库存，程序查不到。
界面上会显示「Apple 澳门没有网上商店，无法查询门店取货库存」并禁用选择。

**Q：我选了上海的门店，为什么邮件里会出现苏州、无锡的门店？**
A：这是 Apple 接口的特性，不是 bug。大陆的库存接口是**按定位返回"附近"有货门店**，
定位上海时会把苏州、无锡、杭州、宁波的门店一起返回来。
程序只会把**你勾选了监控的门店**算进结果，其余的在界面里作为
「附近另有 N 家未监控门店有货」提示你 —— 相当于免费送了你一份周边库存情报。

**Q：界面里的机型目录是实时的吗？**
A：`catalog-cache.json` 里预置了一份抓好的目录，所以首次打开就能直接选。
点「刷新机型目录」会从 Apple 官网重新抓取（约 3 秒）。

**Q：怎么确认它真的在后台跑？**
A：双击 `查看日志.bat`，正常会不断出现 `#N 地区结果更新 [...]`（有变化时）或 `#N 无变化 [...]`（没变化时的简写）。

**Q：日志里出现 `[校验:大陆] 第 N 次：哨兵无数据…`？**
A：这是**正常的自愈机制**。Apple 的接口在会话刚建立、或刚换过定位时经常返回空数据，
程序会自动预热重试，只有拿到可信数据才算一轮有效检查。
所以你**不会**因为接口抽风而收到错误的「无货」结论。

**Q：会不会被 Apple 封 IP？**
A：默认每 60 秒查一次大陆、每 5 秒查一次香港、每 5 秒查一次深圳，每次都带 0–1 秒随机抖动；会话在多次轮询间复用。
香港能查得这么勤，是因为它不需要提交定位、一次请求就能出结果，代价很小；**深圳通道**要提交一次定位，但只查深圳一个城市（3 家门店），代价同样很小，所以给了它和香港同级的间隔。
大陆多城市查询使用独立会话和最多 3 个并发城市任务，15 秒下限只用于网络稳定、监控城市较少的场景。Apple 未公开该接口的轮询配额，过频请求仍可能触发限流；监控多个大陆城市建议把大陆间隔设为 30 秒或更高。
大陆 / 香港 / 深圳间隔各不相同，所以每轮只查「到点」的通道：没轮到的地区在界面上显示「等待下一轮查询」，也不会拿旧数据下「已售罄」的结论。
只监控深圳门店时，优先通道会被自动跳过（和深圳通道查同一个城市），实际只有大陆整轮 + 深圳通道两条通道在跑。

**Q：会不会误报「有货」？**
A：不会。判定依据是 Apple 返回的 `eligibleStores` 是否包含你选的门店编号。
而且每轮都带一个「哨兵料号」（长期有货的 iPad 配件）做健康检查：
哨兵没数据 → 判定本轮不可信 → 重试，绝不把接口故障当成库存结论。
大陆和香港各有自己的哨兵料号。

**Q：程序会打扰我正常用电脑吗？**
A：不会。后台通过隐藏窗口的启动器运行（`wscript` + VBS），
任务管理器里能看到 `node.exe`，但**不会弹出任何窗口、不抢焦点、不弹通知**。
设置界面是你主动开浏览器才出现的，不占桌面。

**Q：电脑睡眠/关机还监控吗？**
A：睡眠会暂停。笔记本建议设成「接通电源时不睡眠」；
或部署到常开的机器 / 树莓派 / 云服务器（用 Docker 最省事）。

## 十、工作原理（技术备注）

### 接口协议（2026-09 实测）

Apple 的门市取货数据在同一套接口下，**大陆和香港都能用**，但有两处关键差异：

1. **老接口 `/shop/fulfillment-messages` —— 已下线，全局返回 404。**
   网上多数现成的 Apple 抢购监控脚本用的都是它，现在都已经跑不通。

2. **现行接口 `/shop/sba/availability-message`** —— 三个坑：

   - **必须先建立 SBA 会话**：先 GET 商品页拿到 `fnode` 令牌，再调
     `/shop/sba/d/init?fnode=...`。不建会话的话，接口只返回送货信息，
     `partAvailableStoresCount` **恒为 0** —— 这是**假无货**，
     HTTP 200、JSON 结构完整，非常有迷惑性。

   - **会话刚建立后的第一次查询偶发返回空数据**，所以程序做了
     「预热 + 哨兵校验 + 重试」。

   - **🇨🇳 大陆必须先提交定位，否则永远返回 0 家店**（同样是假无货）：
     ```
     GET /shop/address/location/update?state=省&city=市&district=区
     ```
     其中 **`district`（区）是必填** —— 缺了它接口一样返回 0，
     这点没有任何文档说明，是踩出来的。
     提交定位后，`eligibleStores` 返回的是**定位点附近有货的门店**，
     会跨市（定位上海能拿到苏州/无锡/杭州的门店），
     所以用户勾选的每个城市都要单独提交一次定位。

拿到数据后，`eligibleStores` 字段就是「哪些门店有货」的门店编号列表。

### 通道与调度（一张表看懂）

| 通道 | 覆盖 | 需要定位 | 间隔 | 说明 |
|---|---|---|---|---|
| `CN` | 所有监控的大陆城市 | 是（每城市一次） | 60 秒 | 一次跑完所有大陆监控城市，最多 3 个城市并发 |
| `HK` | 全港 | 否 | 5 秒 | 一次请求返回全港门店 |
| `SZ` | 深圳一个城市 | 是（一次） | 5 秒 | 与 `CN` 同级，独立会话 / 独立间隔；只在有深圳门店时启用 |
| `PRI` | 优先门店所在城市 + 优先机型 | 视地区 | 20 秒 | 与 `SZ` 查同一城市且不会更勤时自动跳过 |

- 各通道**独立排队、互不阻塞**：大陆的慢查询 / 重试不会拖住深圳。
- 城市级通道（`SZ` / `PRI`）的结果**只覆盖自己那个城市的门店**；
  它写进本地缓存时会记下「这次确认了哪些门店」，其他城市不会拿它的数据下结论。
- 引用缓存时（某地区本轮没查）也要求缓存**覆盖该地区全部监控门店**才复用。

### 门店与定位数据

- **门店目录**：抓自 `apple.com.cn/retail/storelist/` 页面里内嵌的
  `__NEXT_DATA__` JSON（含门店编号、名称、地址、电话、省市）。
  生成结果固化在 `src/stores.js`，离线可用。
- **行政区**：大陆的定位需要「区」，取自 Apple 自己的
  `/shop/address/locality-lookup` 接口，并且**优先采用门店地址里真实出现的那个区**
  （直接取第一项常常会拿到"长沙县""登封市"之类的郊县，把定位带偏）。
  ⚠️ 这是**逐店**属性：深圳 3 家门店分属宝安 / 罗湖 / 南山，
  写成同一个区会让其中两家的定位落在错误的行政区上。
- **深圳通道**依赖这里的区数据提交定位：`state=广东&city=深圳&district=宝安区` 之类。
  定位不提交或区填错，接口一样返回 0 家店（假无货）。

### 机型目录与直达链接

机型目录来自 Apple 各购买页内嵌的 products JSON（含料号/容量/颜色/价格）。
两地页面结构一致，但**导购链接的 slug 规则完全不同**：

- **大陆**：slug 就是**料号的小写形式** ——
  `/shop/buy-iphone/iphone-18-pro/mjyc4ch/a` ✅ 精确到具体颜色
- **香港**：slug 是中文描述 ——
  `/shop/buy-iphone/iphone-18-pro/6.9-吋顯示器-512gb-銀色`

香港这种要靠颜色名翻译反推，所以程序**用页面上真实存在的 slug 集合做校验**：
推不出来就退回机型主页，绝不给出一个 404 的链接。（实测 73×2 = 146 条链接全部精确命中）

> 顺带一个坑：Apple 的商品名里混了普通空格和 `U+00A0` 不换行空格，
> 大陆页用前者、香港页用后者，**同一页里甚至两种都有**。
> 不统一就会把同一款机型拆成两条记录，界面上出现两个"iPhone Duo"。

> Apple 随时可能再改接口。若某天 `--once` 持续报错，多半是又变了；
> 看 `node src/index.js --once` 的具体错误，再对照 `src/apple.js` 顶部注释调整。

## 十二、迁移到另一台电脑

本项目**不含任何硬编码路径**，整个文件夹拷过去、双击 `一键部署.bat` 即可
（已实测：干净环境从零部署 → 装依赖 → 邮箱向导 → 后台任务，全程通过）。

**要带**：全部源码与本目录下的文件，**包括 `catalog-cache.json`**
（里面是预置好的机型目录，带上它新机器首次打开界面就能直接选机型，不用等抓取）

**不用带**（新机器会自动生成）：
`node_modules/`、`.env`（邮箱向导会重新问）、`config.json`（用默认值，进界面重选）、
`monitor.log`、`state.json`、`data/`

## 十三、结束程序
1.点击停止运行后，按照cmd提示操作即可

2.点击卸载程序.bat，即可解除监控事件

3.如果需要删除当前文件夹或者更新版本，提示无法删除时，可以进入Windows任务管理器，搜索node，结束该进程即可。删除前可以保留.env的邮件配置文件，后续版本更新或重装监控事件粘贴进文件夹目录即可，无需重复配置。
