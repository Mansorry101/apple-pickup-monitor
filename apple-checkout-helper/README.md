# Apple 结账速填 · 抢购助手

Chrome 扩展。在 apple.com.cn 结账页点一下悬浮按钮，自动把收货 / 取货信息填完并点「下一步」，你只管付款。

不用发消息、不用切窗口，按钮就在页面右下角，可以拖到任意位置。

---

## 一、安装（1 分钟）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
2. 打开右上角的 **开发者模式**
3. 点左上角 **加载已解压的扩展程序**
4. 选择这个文件夹 `apple-checkout-helper`
5. 首次安装会自动弹出配置页；没弹出就点扩展图标 →「打开设置」

> Chrome 137 以后不再支持命令行加载扩展，必须走上面这个手动步骤。

## 二、第一次使用：把信息填进去

配置页从上到下填一遍，边填边自动保存：

| 区块 | 填什么 | 说明 |
|---|---|---|
| 取货方式 | 门店取货 / 送货上门 | 默认门店取货 |
| 购买人信息 | 姓名、手机号、邮箱 | **必填**，缺了会提示 |
| 收货地址 | 省、市、区、街道、邮编 | 选「送货上门」时才显示 |
| 门店取货 | 姓氏、名字（中文）、身份证后四位、门店名、日期 | 取货页要用，**必填**前三项 |
| 支付方式 | 微信支付 / 支付宝 / 信用卡；**我自己点** / 自动帮我点 | 默认「我自己点」 |
| 发票 | 个人 / 公司其他 / 增值税专用 + 抬头税号 | 默认个人 |
| 执行方式 | 自动点下一步、连跑几步 | 默认已调好，一般不用改 |

填完回到 Apple 页面就行，配置只存在本机浏览器里。

## 三、抢购当天的操作

1. 正常加购，点「结账」进入结账页
2. 看到右下角的黑色「填」按钮，**点一下**
3. 面板里点 **一键填写 + 下一步**
4. 扩展自动走完这 4 步，停在最后一步等你

它会按页面自动判断当前在哪一屏，做对应的事：

| 页面 | 它做什么 |
|---|---|
| **选择取货日期 / 门店** | 选日期（默认最早，可在配置里指定）→ 选最早签到时段 → 按门店名选中门店 → 点「继续填写取货详情」 |
| **填写取货信息** | 姓氏、名字、邮箱、手机号、身份证后四位 —— **整段覆盖旧值**，然后点「继续」 |
| **你需要什么类型的发票？** | 按配置选「个人 / 公司其他 / 增值税专用」，有抬头税号就一起填 → 点「继续选择付款方式」 |
| **支付方式** | 默认**停手等你**：你点完微信支付，按 `Alt+Q`（或点面板「我已选好」），它才点「检查订单」 |
| **检查订单** | **停手**。你核对金额后自己点「立即下单」 |

最后一屏默认不点「立即下单」。想全自动，在设置里打开「自动点立即下单」（见第七节）。

### 和库存监控联动（1.10.0+）

配合本机的库存监控程序（定制版 2.9.0+）使用。监控默认用**专用的下单 Chrome 配置**（和日常 Chrome 分开，数据在监控程序目录的 `browser-profile/`），所以扩展要**装在那个配置里**：双击监控程序的「打开下单浏览器.bat」，在弹出的窗口里按上面第一节装扩展，并登录 Apple 账户、**把要买的机型加进购物袋**。之后的事交给它们：监控发现有货 → 自动打开下单 Chrome 到购物袋 → 扩展点「结账」→ 进入上表的结账流程：

| 页面 | 它做什么 |
|---|---|
| **购物袋** | 点「结账」。购物袋是空的、或同款超过限购（「每名顾客最多可购买 2 个…」）时停下，等你处理好自己点结账，之后继续接手 |
| **登录页** `/shop/signIn` | 停下等你登录或点「以游客身份继续」，进入结账页后自动继续 |
| **结账各页** | 同上表，门店**用监控报告的有货门店**（按优先门店排序，第一家不可取货就换下一家），停在检查订单页 |

- 交接地址形如 `https://www.apple.com.cn/shop/bag#af-handoff=<令牌>@<端口>`，扩展读到后立即从地址栏去掉令牌，再向 `http://127.0.0.1:<端口>` 领取机型和门店（manifest 里因此多了 `http://127.0.0.1/*` 权限，只用来连本机监控程序）
- 进度存在 `chrome.storage.local.afHandoff`，30 分钟后作废；走完或出问题停下后自动清掉
- 监控设置界面的「测试联动」只验证能否领取，面板显示「已接手（测试）」，**不会点结账**
- 无头 Chrome（`--headless`）会被 Apple 拦，只能在正常窗口里用；监控要在已登录的 Windows 桌面上运行

### 支付方式怎么选

默认**自动帮你点**。Apple 的支付 radio 是视觉隐藏的，label 里只有 logo 没有文字，所以扩展按真实标识精确匹配：

```
微信支付  data-autom="checkout-billingOptions-WECHAT"  value="WECHAT"
支付宝    data-autom="checkout-billingOptions-ALIPAY"  value="ALIPAY"
信用卡    data-autom="checkout-billingOptions-CREDIT"  value="CREDIT"
```

分期方案（`installments…`）不会被误选。如果你想自己点，设置页第 4 节改成「我自己点」，流程变成：

1. 扩展一路跑到支付页 → 面板提示「请你手动点微信支付」
2. 你点微信支付（1 秒的事）
3. 按 `Alt+Q`，或点面板上那个已经变成 **「我已选好 → 点检查订单」** 的按钮
4. 扩展点「检查订单」，停在检查订单页

如果你想让扩展自己点，去设置页第 4 节把「这个支付方式谁来点」改成**自动帮我点**。

> 按钮文案是「继续」「下一步」「继续选择付款方式」「检查订单」这类，识别不上时还会用「以继续/下一步/前往开头」兜底，所以 Apple 换文案也不容易卡住。

**支付卡片是怎么点的**：Apple 的支付方式不是 `<button>`，卡片可能藏在任意标签里，甚至是视觉隐藏的 radio。所以按四层找，逐层降级：

1. 找原生 `input[type=radio]`（含 Shadow DOM 里的），用 `value/id/name/data-autom/label 文本` 匹配「微信支付」并排除「分付/分期」，直接点 radio；点不动就点它的 label
2. 按 `data-autom` / `id` / `name` 里出现的 `wechat` 之类定位
3. 用 TreeWalker 按**文本节点**找（不限标签，div/td/span 都能捞），点它的父元素
4. 还不行就**按坐标点**：取那段文字的中心点，用 `elementFromPoint` 找到真正接住鼠标的元素，派发完整事件序列 —— 和真人点击落点一致，能绕开各种奇怪的 DOM 结构

点击用的是 `pointerdown → mousedown → pointerup → mouseup → click` 完整序列，因为 Apple 有些组件只监听 `pointerdown`。

四层都没成时**不会盲点「检查订单」**，而是停下来告诉你手动点一下，并把页面上找到的单选项打出来。

**快捷键**：`Alt + Q` 不用点按钮，直接触发。

**四种模式**（面板里的按钮）：

- **一键填写 + 下一步** — 日常用这个，走完当前页并进入下一步
- **只填不点** — 只填字段，按钮你自己点，最保险
- **自动跑到底** — 连续走完 4 步，停在检查订单页
- **记录本页字段** — 见下面「识别不准怎么办」

## 四、取货人信息为什么单独填

Apple 取货页要求「姓名与取货时出示的证件完全一致」，而且**下单后不能改**。取货页是两个框：

- **姓氏** —— `张`
- **名字** —— `三`

**大陆身份证填中文**，护照才填英文/拼音。这两个字段在设置页第 3 节，和「购买人姓名」是分开的（购买人姓名用于配送地址和发票）。

身份证只填**后四位**（Apple 只校验后四位，不用填完整号码）。

## 五、它是怎么认出字段的

Apple 结账页的输入框没有稳定的中文 `name`，所以我按三层信息识别：

1. **控件自身属性** —— `data-autom`、`name`、`id`（只取最后一段）、`placeholder`、`aria-label`、`autocomplete`
2. **label 文本** —— `label[for]`、包裹式 `<label>`、`aria-labelledby`
3. **邻近文本** —— 控件上方的说明文字（弱提示，只在前两层都认不出时才用）

关键词表覆盖中英文：`收货人/姓名/取货人` → 姓名，`手机/电话` → 手机号，`省/自治区/直辖市` → 省，`街道/地址` → 街道地址，`邮编` → 邮编，`后四位` → 身份证后四位……

> **`id` 只取最后一段**是有原因的：Apple 的取货字段 id 长这样 `checkout.pickupContact.selfPickupContact.selfContact.address.lastName`，整串里带 `address`。如果按整串匹配，「姓氏」会被判成「街道地址」，结果什么都不填、页面上还留着旧值。取最后一段 `lastName` 就对了。

写入用的是原生 `value` setter + `input`/`change` 事件，能骗过 React 这类受控组件（Apple 结账页就是 React 19）。取货页常带掩码旧值（`a*******1@example.com`、`•••••••0000`），所以填之前会先 `select()` 全选 + 发 `Backspace`，再整段写入，保证是覆盖而不是拼接。

省市区是异步级联的，扩展会**轮询等目标选项出现**（最多 4 秒）再选，不会因为网慢就填错。

另外从 Apple 结账页的 JS 里确认了这些真实标识，已写进按钮识别逻辑：

```
shipping-continue-button      fulfillment-continue-button
continue-button-review        continue-button-with-applecard-button
fulfillment-pickup-store-search-button   bag-storelocator-confirmstore
pickup-availablewindow-dropdown          authorizePayment
card-number-input
```

## 六、识别不准怎么办

Apple 改版、或者某个字段填错了，不用改代码：

1. 在结账页点悬浮按钮 → **记录本页字段**
2. 面板会显示当前页面类型 + 每个输入框的识别结果，**同时自动复制成 JSON 到剪贴板**
3. 想让我改，直接把剪贴板内容贴给我。这份 JSON 现在包含：页面类型、所有按钮文案、可见输入框、**所有单选项（含隐藏的、含选中状态）**、**所有含「微信/支付」文字的元素及其三层祖先标签/class/role**、页面里的 iframe
4. 自己动手也行：打开设置页拉到底部的 **字段映射**，把认错的字段在下拉里改成正确的

改完立刻生效，扩展会优先用你指定的映射。

## 七、安全与边界

- 数据只存在 `chrome.storage.local`，**不上传**；唯一的额外连接是联动时向本机 `127.0.0.1` 的监控程序领取交接信息
- 默认到检查订单页**停手**。设置页「执行方式」里勾选「到检查订单页自动点『立即下单』」后（勾选时会弹窗确认），扩展只在确认是检查订单页时点一次「立即下单」，**90 秒内不会再点第二次**；「只填不点」模式永远不点
- 不在检查订单页时，有一道不依赖页面识别的硬拦截：文案含「立即下单 / 提交订单 / 确认付款 / 支付 ¥」或 `data-autom` 为 `authorizePayment` 的按钮不会被当成「继续」去点
- 同一页面连续出现 3 次、或点了按钮 3 秒没反应，会停下来，避免重复提交
- 短信验证码**永不自动填**，检测到就停下来提示你
- 登录墙不处理，需要你自己登录
- 换电脑用「导出配置 / 导入配置」

## 八、已知限制

- 只在 `apple.com.cn` / `apple.com` 生效
- 页面类型是靠文案判断的（「选择取货日期」「填写你的取货信息」「你需要什么类型的发票」「支付方式」「立即下单」）。Apple 大改文案时，面板日志会显示「当前页面：未识别页面」，这时点「记录本页字段」把 JSON 贴给我，我加一条识别规则
- 门店是「优先精确匹配门店名，匹配不到按关键词，再不行选第一个可取货的」。要指定门店就把「门店名」写全，如 `Apple 深圳万象城`
- 日期留空 = 选最早可取的；要指定某天就填日号，如 `24`
- 抢购时网络抖动，如果卡在「页面没有变化」，把设置里的**每步延迟**调到 300–500 毫秒再试
- 如果面板提示「支付方式没选上」，日志里会列出页面上找到的单选项。点「记录本页字段」把 JSON 贴给我，我照着加一条规则
